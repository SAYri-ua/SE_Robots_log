# SE Robots log

Плагін для WordPress, який збирає статистику запитів пошукових роботів до сайту. Дані зберігаються в базі даних WordPress та відображаються в адміністративній панелі.

**Версія:** 0.0.1  
**Автор:** [SAYri](https://sayri.work/)  
**Ліцензія:** GPLv2 або новіша

## Можливості

- Облік запитів роботів за значенням заголовка `User-Agent`.
- Статистика для кожної пошукової системи за сьогодні, вчора, останні 7, 30 і 90 днів.
- Загальна кількість збережених запитів та дата останнього відвідування.
- Додаткове збереження адрес запитаних сторінок із переглядом за сьогодні та вчора.
- Налаштування строку зберігання статистики.
- Очищення журналу URL або скидання всієї статистики через панель керування.

## Підтримувані пошукові системи

| Система | Ідентифікатори в `User-Agent` |
| --- | --- |
| Google | `Googlebot`, `Googlebot-Image`, `Googlebot-Video`, `Storebot-Google` |
| Bing | `bingbot`, `MicrosoftPreview`, `BingVideoPreview` |
| Yahoo | `Yahoo! Slurp`, `Slurp` |
| DuckDuckGo | `DuckDuckBot` |
| Apple | `Applebot` |
| Yandex | `YandexBot`, `YandexImages`, `YandexVideo` |
| Baidu | `Baiduspider` |
| Qwant | `Qwantbot` |
| Naver | `Yeti` |
| Mojeek | `MojeekBot` |
| ChatGPT | `OAI-SearchBot`, `ChatGPT-User` |

Пошук ідентифікатора виконується в будь-якій частині `User-Agent` без урахування регістру. Поле `bot` містить знайдений ідентифікатор; якщо збігаються загальний і конкретніший варіанти, зберігається конкретніший, наприклад `Googlebot-Image`. Один запит додається до статистики лише однієї системи.

## Вимоги

- Встановлений WordPress із доступом до бази даних.
- Обліковий запис адміністратора для активації та налаштування плагіна.
- Можливість створення таблиць у базі даних під час активації.

Мінімальні та перевірені версії WordPress і PHP у проєкті не зазначені.

## Встановлення

1. Створіть каталог `SE_Robots_log` у директорії `wp-content/plugins/` вашого сайту.
2. Скопіюйте до нього файл `sebotslog.php`:

   ```text
   wp-content/
   └── plugins/
       └── SE_Robots_log/
           └── sebotslog.php
   ```

3. У панелі WordPress відкрийте **Плагіни → Встановлені плагіни**.
4. Активуйте **SE Robots log**.
5. Відкрийте **Налаштування → SE Robots log** або **Майстерня → SE Robots log**.

Під час активації плагін створює необхідні таблиці та початкові налаштування. Окрема збірка або встановлення залежностей не потрібні.

## Використання

Після активації плагін автоматично перевіряє запити на етапі `init` WordPress. Якщо `User-Agent` відповідає одному з підтримуваних шаблонів, запит додається до статистики.

На сторінці плагіна доступна таблиця з кількістю запитів для кожної пошукової системи. Щоб переглядати адреси сторінок, увімкніть запис URL та збережіть налаштування. Натискання на лічильник за сьогодні або вчора відкриває відповідний список збережених адрес.

Запис URL починається після його ввімкнення: адреси попередніх запитів не відновлюються.

## Налаштування

| Параметр | Початкове значення | Призначення |
| --- | --- | --- |
| Строк зберігання статистики | 90 днів | Визначає, які старі записи статистики видаляються |
| Збереження URL | Вимкнено | Додає адреси запитаних сторінок до окремого журналу |
| Строк зберігання URL | 2 дні | Заданий константою `SEBOTSLOGS_URLS_LIFETIME_DEFAULT` у коді; окремого поля в панелі немає |
| Очищення журналу URL | За вибором адміністратора | Видаляє всі збережені адреси |
| Скидання статистики | За вибором адміністратора | Очищає обидві таблиці журналу |

Очищення та скидання виконуються після збереження форми й безповоротно видаляють відповідні записи.

Старі записи очищаються під час роботи плагіна, а не за окремим розкладом: статистика — під час відкриття сторінки плагіна та частини запитів роботів, URL — під час запису нової адреси. Тому строки зберігання не гарантують видалення точно через задану кількість годин.

## Зберігання даних

Плагін використовує дві таблиці з префіксом поточної інсталяції WordPress:

| Таблиця | Вміст |
| --- | --- |
| `{prefix}sebotslogs_se` | Назва пошукової системи, поле `bot`, дата й час запиту |
| `{prefix}sebotslogs_urls` | Назва пошукової системи, поле `bot`, дата й час запиту, адреса сторінки |

Наприклад, для префікса `wp_` це `wp_sebotslogs_se` і `wp_sebotslogs_urls`.

Налаштування зберігаються як опції WordPress: `sebotslogs_logs_lifetime` і `sebotslogs_urls_into_db`. Дата й час записів беруться через `current_time()` WordPress.

## Особливості обліку

- Розпізнавання спирається на шаблони `User-Agent`; перевірки IP-адрес або DNS немає. Статистика відображає запити з відповідними заголовками, а не підтверджену автентичність роботів.
- Лічильники показують кількість запитів, а не кількість унікальних роботів чи сторінок. Значення «Всього» охоплює лише записи, які ще зберігаються в базі.
- Запити, які обслуговує кеш або CDN без запуску WordPress, не потрапляють до журналу.
- Збережена адреса містить ім’я сервера та `REQUEST_URI`, включно з параметрами запиту, якщо вони є.
- Адміністративний інтерфейс поточної версії містить англомовні написи.

## Деактивація та видалення

Деактивація зупиняє роботу плагіна та залишає таблиці й налаштування в базі даних.

Видалення через стандартну сторінку плагінів WordPress видаляє обидві таблиці та опції плагіна. Ручне видалення файлів не запускає цю процедуру й залишає дані в базі.

## Структура проєкту

```text
SE_Robots_log/
├── sebotslog.php   # Код плагіна, адміністративний інтерфейс і робота з базою даних
├── README.md       # Документація
└── tests/
    └── sebotslog_test.php   # Перевірки розпізнавання, запису запитів і статистики
```

## Перевірка змін

Тести виконують код плагіна з тестовими функціями WordPress та базою SQLite у пам’яті. Для їх запуску потрібен PHP з розширенням `pdo_sqlite`:

```sh
php -l sebotslog.php
php -d extension=pdo_sqlite tests/sebotslog_test.php
```

Перевіряються всі 20 ідентифікаторів роботів, регістр і позиція в `User-Agent`, збереження URL, лічильники для всіх 11 систем та межі днів. Це локальні перевірки; повна інсталяція WordPress із MySQL для них не використовується.
